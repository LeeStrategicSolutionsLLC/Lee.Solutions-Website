# Lee Solutions Website

This is the source for the Lee Solutions marketing website
([lee.solutions](https://lee.solutions)) and the matching print materials
(business card and 5x8 leave-behind).

There is no build step, no framework, and no server-side code — it's plain
HTML, CSS, and a small amount of JavaScript. Any web browser can open it
directly, and any text editor can change it.

## What's in here

- **`site/`** — the live website. Each folder is one page:
  - `/` (`site/index.html`) — home
  - `/what-we-do/`
  - `/how-we-work/`
  - `/about/`
  - `/contact/`
  - `/card/` — digital business card page (also offers a downloadable `.vcf`
    contact file)
  - `/start/`
  - `/client-stories/` — client story listing
  - `/client-stories/template/` — an internal template for adding a new
    client story. It's not linked from the site's navigation on purpose, so
    it won't show up for visitors until it's copied into a real story page
    and linked in.
  - `site/css/` — shared styles and design tokens (colors, spacing, etc.)
  - `site/js/` — small scripts (page behavior, background ambient effect)
- **`print/`** — the business card and 5x8 leave-behind:
  - `business-card.html`, `leave-behind.html`, `print.css` — the editable
    source
  - `print/build/` — the print-ready PDFs generated from that source
  - `print/qr/` — the QR code images used on the card and leave-behind

## How to preview it on your own computer

No install is required. To just look at a page, double-click any
`index.html` file (for example `site/index.html`) and it opens in your
browser.

To preview it the way a visitor would — with all the page links working —
run a tiny local server from the `site` folder instead of opening the file
directly:

```
cd site
python3 -m http.server 8000
```

Then open `http://localhost:8000` in a browser. (Any simple static file
server works here — this is just the one that's built into most computers
already.)

## How to make a change

1. Open the relevant `index.html` file in a text editor and edit the text
   or markup directly.
2. Preview the change locally (see above) to make sure it looks right.
3. Save, commit, and push to the `main` branch on GitHub.
4. The live site updates automatically within about a minute of the push —
   see **How it deploys** below.

There's no build process to run and nothing to compile. If a page looks
right in the local preview, it will look the same once it's live.

## How it deploys

Every push to the `main` branch on GitHub automatically publishes the
`site/` folder to the live website. This is handled by a GitHub Actions
workflow at `.github/workflows/pages.yml` — you don't need to trigger
anything by hand.

You can watch a deploy happen (or check why one failed) under the repo's
**Actions** tab on GitHub.

## Where it's hosted

- **Hosting:** GitHub Pages, on this repository
  (`LeeStrategicSolutionsLLC/Lee.Solutions-Website`). Hosting itself is
  free — GitHub Pages has no charge for a public repo like this one.
- **Domain:** `lee.solutions`, registered and managed at
  [Porkbun](https://porkbun.com). DNS is pointed at GitHub Pages via four
  A records on the root domain. Check your Porkbun account for the domain's
  renewal date and price — that's the only recurring cost tied to this
  project.
- **HTTPS certificate:** issued and auto-renewed by GitHub — no action
  needed unless the domain's DNS changes.

## When something breaks

- **The whole site is down / showing an old version:** Check the repo's
  **Actions** tab on GitHub for a red (failed) run. Click into it to see
  the error. Most failures are a syntax mistake in an HTML/CSS file from a
  recent edit.
- **`lee.solutions` shows a certificate warning or "can't connect":** This
  usually means the domain's DNS was changed and GitHub needs a few minutes
  to hours to reissue the certificate. In the repo, go to **Settings →
  Pages** and confirm the custom domain field still shows `lee.solutions`
  with no error underneath it.
- **A page shows a 404 / "site not found":** Confirm the page's folder has
  an `index.html` file inside it, and that any links to it use a trailing
  slash (e.g. `/about/`, not `/about`) — that's what this site's structure
  expects.
- **The QR codes or print PDFs need to change:** Edit `print/business-card.html`
  or `print/leave-behind.html`, then open that file in a browser and use
  **Print → Save as PDF** to regenerate the file in `print/build/`. There is
  no automatic build for the print files — they're regenerated by hand
  whenever the source changes.
